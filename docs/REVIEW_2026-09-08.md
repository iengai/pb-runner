4.    - **Resolution (2026-09-08):** new `crates/runner/src/exchange_config.rs` `ExchangeConfigurator` (lazy per-symbol `update` before the wave's creates, done-set, `min(5*2^(n-1), 60)+U(0,0.5)` s backoff, rate-limit-like failure stops the wave's configuration, 0.2 s pause after each success, creates on pending symbols skipped without a budget charge; leverage = `min(live.leverage (coin override aware), market max)`; margin mode cross as `_resolve_margin_policy_for_symbol`), wired in `execute.rs` `Executor::execute` (SPEC 3.1 step 7); `crates/exchange-bybit/src/bybit/mod.rs` `is_unified_account` (ccxt `is_unified_enabled`: `/v5/user/query-api` `unified`/`uta`) and `configure_symbol` (unified -> `/v5/account/set-margin-mode {setMarginMode: REGULAR_MARGIN|ISOLATED_MARGIN, leverage}`, classic -> `switch-isolated`; then `set-leverage`; 110026/110043/"not modified" tolerated); `live.rs` `configure_exchange` (hedge mode always, 3 attempts on network errors as `init_markets`, re-asserted hourly). Tests `lazy_configuration_with_backoff_and_rate_limit_stop`, `backoff_and_leverage_arithmetic`. Nothing aborts the process on a per-symbol failure.
5. Exit-30 restart semantics: main.rs exits immediately when the budget trips; Python sleeps 60 s and stops after max_n_restarts_per_day (passivbot.py:22690-22740). Each ECS restart repeats warmup + the configuration burst; persistent faults restart-loop at ECS speed behind the shared egress EIP (mod.rs maps 403 -> RateLimited) and can hurt other bots.
   - **Resolution (2026-09-08):** `crates/runner/src/main.rs` `run_live` / `run_bot`: Python's `main()` loop in-process -- budget trip (or a failed warmup / configuration) tears the bot down, sleeps the 60 s cooldown, rebuilds a fresh runner + executor (fresh error budget, as `setup_bot`), counts restarts over 24 h and exits 30 once `len(restarts) > live.max_n_restarts_per_day`. CONTRACT.md section 2 documents what pbtb-rust provides: its task-state-change lambda restarts a stopped task only on a memory-related stop (`exit_code == 137` and not `UserInitiated`), so a non-OOM exit leaves the bot stopped until the user starts it, exactly like the Python image; the daily cap therefore lives in-process and is not persisted. D19 item 5.

# Second pass (2026-09-08, read-only subagent over commit f48ac39)

1. HIGH. Failed/ambiguous creates were not remembered by the 15 s recent-execution guard (Python `_remember_ambiguous_create`, executor.py:1090-1100/1143 -> `add_to_recent_order_executions`): a timed-out create the venue executed late could be duplicated 2 s later; a deterministic rejection burned the error budget ~7x faster. **Resolution:** `execute.rs` pushes every failed create and every order of a length-mismatched batch into `recent`.
2. MEDIUM. A symbol with exposure dropped from the cycle (missing ticker/market/candles) was also dropped from the engine's position/exposure accounting, freeing a slot for a new entry; Python raises the whole cycle (market_data.py:634-640). **Resolution:** `live.rs` fails the cycle when any skipped symbol has exposure (flat symbols are still skipped individually).
3. MEDIUM. The hedge-mode assert retried only on `Network`; ccxt's RateLimitExceeded/DDoSProtection/ExchangeNotAvailable subclass NetworkError (errors.py:176-204), so Python retries rate limits too. **Resolution:** `set_hedge_mode_with_retries` retries `RateLimited` as well.
4. LOW. `tokio::signal::ctrl_c()` only armed inside the sleep `select!`; a SIGINT outside those windows is swallowed (dev only; ECS sends SIGTERM, which neither bot handles). Not changed.
5. LOW. The cancel-first barrier bypass for market panic closes does not exist on Python's normal planning path (`_is_dedicated_protective_market_panic` needs `configure_creations=False`, passed only by the HSL protective-panic path passivbot_hsl.py:8191/8335, which the runner does not use, D16 item 3). **Resolution:** bypass removed in `reconcile.rs`; test updated.
6. LOW. `reduceOnly` is sent on every create while Python's Bybit adapter never sends it (bybit.py:542-551). Safer if anything (110017 rejections instead of accidental increases); kept, noted.
7. INFO. Persistent startup faults reach exit 30 after ~11 x (60 s + warmup) and the bot stays stopped (pbtb-rust restarts only exit 137), same as the Python image.
