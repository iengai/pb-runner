# Pre-live review findings (2026-09-08, same-tier subagent, read-only)

1. Fills and closed-pnl are fetched with `startTime` only; Bybit returns [startTime, startTime+7d] when endTime is absent (Python bybit.py:495-500 documents it and walks backwards by endTime, bybit.py:279-308; closed-pnl uses explicit 7-day windows, bybit.py:200-225). Runner: exchange-bybit mod.rs fetch_fills/fetch_closed_pnl send only startTime; live.rs warmup asks since=now-30d and refetches from self.fills.last() only when non-empty. Consequences: warmup loads days -30..-23 only; fills never fetched again on an empty account; trailing anchors fall back to pos.updated_ms; last_increase_fill_ts None so risk_entry_cooldown never blocks; realized_pnl_cumsum stale.
2. Planning-cycle errors: main.rs logs plan() errors and continues forever, no budget, no restart, no market reload. Python routes loop exceptions through _handle_execution_loop_failure -> restart_bot_on_too_many_errors (passivbot.py:6183-6240, 20544-20566) and reloads markets hourly (21665-21675, init_markets 3920). Runner loads markets once and builds the universe from that static map. Scenario: delisted approved coin -> fetch_tickers misses it -> SnapshotError::Incomplete -> plan() fails every 2 s -> no cancels/creates for ANY symbol. Same class: per-symbol kline error (`?`), 10002 clock skew, a position whose market is no longer Trading (parse_markets drops it -> position/orders vanish from view).
3. Engine execution_type=market orders are sent as GTC limit: NewOrder has no order type, order_body hard-codes "Limit" (mod.rs ~549; execute.rs ~530-541 only clears post_only). Python sends type=order["type"] (passivbot.py:22351-22367). Also the ideal keeps limit=false while the resting order normalises limit=true (reconcile.rs ~222), and `limit` is in the exact key and tolerance cohort -> never matches -> cancel + recreate every cycle (panic closes bypass the barrier). Triggers: hsl.panic_close_order_type="market" or market_orders_allowed=true.
4. Startup exchange configuration is all-or-nothing, burst-sent, wrong endpoint: live.rs ~352-385 configures the whole universe sequentially, any unexpected error aborts via `?`; mod.rs ~801-835 calls /v5/position/switch-isolated per symbol tolerating only 10001/110032/not-modified. Python configures lazily per symbol with try/except, 5 s exponential backoff, 0.2 s pause (passivbot.py:10149-10240, 10256-10275); on a unified account ccxt routes set_margin_mode to account-wide /v5/account/set-margin-mode (ccxt bybit.py:6692-6708), never switch-isolated. set_hedge_mode is gated on live.hedge_mode (template default false) while Python always calls set_position_mode(True) (bybit.py:584-590 from init_markets:3929) and both always send positionIdx 1/2. Scenarios: 100+ approved coins -> 200+ POST burst -> 10006 -> abort -> restart loop; fresh one-way account -> every create rejected -> exit 30 every ~10 batches.
5. Exit-30 restart semantics: main.rs exits immediately when the budget trips; Python sleeps 60 s and stops after max_n_restarts_per_day (passivbot.py:22690-22740). Each ECS restart repeats warmup + the configuration burst; persistent faults restart-loop at ECS speed behind the shared egress EIP (mod.rs maps 403 -> RateLimited) and can hurt other bots.
6. time_in_force default: main.rs ~127-131 reads the raw config and defaults post_only=true when live.time_in_force is absent; Python's default is good_till_cancelled (config/schema.py:446, bybit.py:545-549) and ConfigView already carries the template value (bot_params.rs ~715-750). PostOnly closes at/through the book get cancelled by Bybit while counted as creates_ok.
7. A failed cancel does not block the symbol's other creates in the same wave (execute.rs ~569-584). Python adds the symbol to state_change_detected_by_symbol on a non-acknowledged or already-gone cancel and skips that symbol's creates for the wave (RECONCILE_SPEC 3.1 step 6 / 3.2); the runner's barrier is per (symbol, pside).
8. Minor: fills/closed_pnl buffers grow unbounded (live.rs ~857-865, ~401-411) and are scanned linearly; Python prunes to the lookback. normalize_open_order picks the reduce-only rule from config hedge_mode (reconcile.rs ~206-214) whereas Python uses the order's positionIdx (bybit.py:83-97). Recent-execution guard stamps creates with loop-start now (window shrinks by planning time). Cancel-batch length mismatch counts toward the error budget (Python only marks dirty; unreachable with join_all).
